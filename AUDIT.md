# Browser 0.2: аудит перед сборкой

Дата: 12 ноября 2026. Объём: текущий `src/`, конфиг, упаковка и сценарии
настольного приложения. Исходный движок Obscura в архивной ветке не входит
в поставку и не проверялся как часть Browser.

После каждого набора исправлений выполнялся повторный проход. Последний проход
по указанному объёму: **0 новых найденных проблем**. Это результат проверок,
а не доказательство отсутствия любых возможных ошибок.

## Проход 1: архитектура и основной интерфейс

Исправлено:

- Полное пересоздание списка вкладок при фоновых событиях. Теперь используются
  стабильные DOM-узлы, обновляются только изменённые поля.
- Отсутствие фокуса поиска при открытии пустой вкладки.
- Отложенное сохранение после закрытия окна могло затереть восстановление вкладок
  на Mac. Закрытие теперь синхронно сохраняет состояние и отменяет таймер.
- Одновременные операции загрузки расширений. Синхронизация теперь последовательна.
- Потеря черновика конфига при переключении панелей.
- Несовпадение области настоящей веб-страницы и интерфейса при произвольном CSS.
  Размеры WebContentsView теперь следуют измеренному `#viewport`.

Убраны закладки и экспорт страницы. Монолит разделён на модули жизненного цикла,
окон, вкладок, конфига, расширений, загрузок и безопасности. UI разделён на
контроллер, темы, панели и вспомогательные функции. Убрана периодическая
перерисовка без изменений и секундный опрос конфига; используются уведомления ОС.

## Проход 2: безопасность и пограничные состояния

Исправлено:

- Обращение к уничтоженному RenderFrame в обработчике приватности могло прервать
  сетевой callback. Добавлена обработка исчезновения фрейма; неизвестный контекст
  не получает сторонние cookies.
- Обход списка трекеров через эквивалентный DNS-домен с точкой в конце.
- Одинаковые сочетания с разным порядком модификаторов и платформенными алиасами.
  Конфликты проверяются отдельно для Windows и Mac.
- Гонка автофокуса: позднее обновление пустой вкладки могло украсть фокус адреса.
- Удалённые поля старого конфига делали его невалидным. Добавлена миграция v1 → v2.

Проверены границы IPC, запрет Node.js для сайтов, sandbox, context isolation,
блокировка локальных/привилегированных URL, HTTP(S)-шаблоны поиска, запросы
разрешений и отсутствие отключения TLS-проверок в приложении.

## Проход 3: жизненный цикл, настройки и производительность

Исправлено:

- Вкладка, долго находившаяся активной, могла засыпать сразу после переключения.
  Время бездействия теперь начинается при потере активности.
- Неудачное восстановление при лимите вкладок удаляло запись из истории закрытых.
- При восстановлении терялись сохранённые названия и состояние mute.
- Завершение сохранения конфига могло очистить более новый черновик.
- Сброс настроек оставлял старый незавершённый черновик в редакторе.
- Пресеты использовали захваченное старое состояние при частичном конфиге.
- Скрытый через CSS viewport не скрывал нативное содержимое.
- Скачивание в новой вкладке оставляло пустую веб-страницу вместо стартового экрана.
  Загрузки теперь восстанавливают предыдущий документ, а лишний пустой renderer
  закрывается после завершения скачивания.

Список блокировки компилируется в Set с поиском по DNS-суффиксам. Локальный
синтетический замер: 10 000 запросов, 10 000 доменов, отсутствующий домен:
линейный перебор 6964 мс, кэшированный поиск 3 мс. Это замер одной функции,
не сравнение скорости Browser с другими браузерами.

## Проход 4: повторное ревью и проверка регрессий

Проверены повторно сохранение/закрытие/восстановление, переключение вкладок,
область сайта при пользовательском CSS, черновики и сброс, конфиг при внешнем
редактировании, расширения, загрузки, разрешения и настройки стекла.
Визуально просмотрены стартовый экран и настройки.

В тестовом запуске обнаружен флаг `--no-sandbox`, который Playwright добавляет
по умолчанию. Для тестов явно включён `chromiumSandbox: true`; добавлена проверка
отсутствия флага и фактических WebPreferences сайта. Приложение сам этот флаг
не добавляло. Полный набор затем выполнен с включённой песочницей.

## Границы проверки

После завершения аудита `npm run pack` успешно собрал локальный Linux-пакет.
Отдельно запущен именно упакованный бинарник: `app.isPackaged === true`, версия
`0.2.0`, sandbox не отключён. Проверены загрузка интерфейса из ASAR, IPC и
навигация на реальную страницу локального сервера.

Нативный вид acrylic/vibrancy зависит от ОС и её настроек. Локальный X11-прогон
проверяет конфиг, CSS, принятие оконных параметров и перезапуск, но не доказывает
визуальную корректность эффектов Windows/macOS. Целевые пакеты проверяются
отдельными CI jobs; нужен и ручной прогон на Windows 11 и Apple Silicon.

Chrome-расширения ограничены API Electron; совместимость со всеми расширениями,
DRM, passkeys и автоматические обновления не обещаются. Windows-пакеты без
сертификата, Mac использует ad-hoc подпись без notarization. Малый список
трекеров не является полным блокировщиком рекламы. Эти ограничения описаны
в README и не учитываются как исправленные ошибки.
